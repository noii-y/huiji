# 基线 · 整句翻译（阶段 2A）

这份文档记录整句翻译原型的实测结果。一句话结论：**离线端侧这条路走得通，而且比预想的快——延迟中位数 83ms，88% 的句子质量在 3 分以上。**

所有数字都在这台机器上、用 release 级推理实测，不是估的。

## 探针怎么搭的

- 模型：Helsinki-NLP 的 opus-mt-zh-en（Marian 架构，约 77M 参数，专门中译英），用 CTranslate2 转换后的版本（HuggingFace：jiangzhuo9357/opus-mt-zh-en-ct2）。model.bin 只有 79.6MB，加两个分词器共约 81MB。
- 推理：CTranslate2 4.8.2，device=cpu、compute_type=int8，beam_size=2。
- 分词：SentencePiece（source.spm / target.spm）。
- 工具脚本：huiji/tools/translate_probe.py。
- 测试集：huiji/评测/翻译/测试集.tsv，100 句，分九类，都是贴近真人的口语句子。
- 正式计时前预热两句，把首次量化和构图开销排除。

## 延迟

第一版没加任何防重复，模型会在个别句子上陷入循环，出现 1.3–1.5 秒的异常值。加上 repetition_penalty=1.2、no_repeat_ngram_size=3 后，循环消失，数字如下（端到端，含分词和解码）：

| 指标 | 毫秒 |
|---|---|
| 中位数 | 83.2 |
| 均值 | 97.5 |
| P90 | 147.3 |
| 最快 | 30.7 |
| 最慢 | 593.5 |

开发计划定的门槛是中位数 800ms，实测 83ms，余量非常大。

## 质量

按 1–5 分逐句人工打分（标准：5 通顺准确、3 能猜懂但别扭、1 不能用），逐句分数见《质量评分.tsv》：

| 分数 | 句数 |
|---|---|
| 5 | 20 |
| 4 | 27 |
| 3 | 41 |
| 2 | 10 |
| 1 | 2 |

**≥3 分共 88 句（88%），均值 3.53。** 门槛是“多数在 3 分以上”，实测 88%，达标。

日常聊天、生活、工作、长句这几类表现最好，很多句子可以直接用，比如：
- I just got off work and was on my way home.
- He said he would finish his report before the end of work, but I thought it might be too late.
- The key is under the door mat. You can open the door yourself.

## 短板和归因

低于 3 分的 12 句，问题很集中：

1. **网络流行语**：摸鱼被译成摸鱼的动作、破防译成“拆散家庭”、神仙颜值整句混乱。这类词更新快，小模型训练时根本没见过。
2. **个别专名**：高铁译成 high-calor / tall train。
3. **数字**：三千二译成 $32,000（多了一位）。
4. **词重复**：不少句子意思对，但带着 tonight tonight、rain rain 这种小重复，影响观感。
5. **个别漏语义**：“我把 Wi-Fi 密码忘了”被译成“你知道是多少吗”，丢了“忘了”这层。

## 对照决策门槛

开发计划的规则是：端侧中位数压到 800ms 内、质量多数 ≥3 分，端侧就作为默认。两条都满足，而且余量不小。**结论：整句翻译默认走离线端侧，云端作为可选的质量增强，不强制。** 这也符合灰迹本地优先、数据不出本机的定位。

## 一个绕不开的工程问题

探针是 Python + CTranslate2，产品是 Rust。端侧推理引擎怎么进 Rust，有三条路，阶段 3 要定：

| 路线 | 好处 | 代价 |
|---|---|---|
| Rust FFI 包 CTranslate2 | 性能、质量和探针完全一致 | 要写 unsafe FFI、打包 C++ 运行库，最复杂 |
| 用 candle 加载同类模型 | 纯 Rust，青简已依赖 candle | CPU 优化弱于 CT2，要转模型、可能得自己补 Marian 网络结构 |
| 用 onnxruntime 的 Rust crate（ort） | ort 带预编译库、CPU 优化好，工程上比 FFI CT2 干净 | 要先把 Marian 导出成 ONNX |

初步倾向 ort 这条中间路线，具体等把模型转一遍再定。

## 下一步

1. 测一版 NLLB-200-distilled-600M 作对照，看专名和流行语能不能救、延迟还能不能接受，判断要不要换更强的端侧模型。
2. 在 cli 上把“打整句拼音 → 本地转中文 → 端侧译文”这条产品路径打通（现在探针只接受中文原句）。
3. 流行语和专名可以先用本地术语表兜底（高铁→high-speed rail），不必全指望模型。
