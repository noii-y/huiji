### 做了什么

**1. 编译工具链**

- 装了 Visual Studio 2022 生成工具（MSVC v143、Windows 11 SDK），Rust 在 Windows 上链接要靠它。
- 装了 rustup，工具链 `stable-x86_64-pc-windows-msvc`，rustc / cargo 都是 **1.99.0**。
- 用 hello world 端到端验过：cargo 能编译、能调用 MSVC linker、能跑出结果。

**2. GitHub 账号和 fork**

- 账号统一用 **noii-y**，旧的 lvhai321 凭据已从 Windows 凭据管理器删掉，git 全局身份也清空了，避免以后提交串号。
- gh CLI 用设备码方式登录 noii-y。
- 把 `qingjian-team/qingjian` fork 到 noii-y 名下，clone 到 `app/`。
- 远程配置：`origin` 指向 noii-y 的 fork，`upstream` 指向青简官方，以后能拉上游更新。

**3. 编译原版**

- 平台无关的核心链加上命令行工具 qingjian-cli：编译通过，耗时 **18 分 23 秒**。
- Windows 的两个产物 qingjian-windows-server 和 qingjian-windows-tsf（版本都是 0.1.5-dev）：编译通过，耗时 **4 分 53 秒**。
- 产物在 `app/target/debug/`：`qingjian-server.exe` 和 `qingjian_tsf.dll`。

**4. 跑了一下 cli**

`cargo run -p qingjian-cli -- ni hao shi jie`，逐字查询，结果符合预期：

- ni 首选「你」、hao 首选「好」、shi 首选「是」、jie 首选「姐」。
- 每个候选旁边带着英文释义，比如「你 pron. you」「好 adj. good」。
- 加载的词库有 92825 条、英文释义 232213 条、英文词 94568 个、emoji 9587 个。
- 单次查询总耗时 1～4 毫秒。

这一步也顺手确认了用户最初提的问题：青简的翻译是**挂在单个词/字上的注解**，输入一串拼音，它不会给出整句话的翻译。整句翻译确实是空白。

### 踩到的坑

- **rustup 安装中途被打断，工具链装残了**，表现是工具链目录在、但 `bin/` 里没有 rustc.exe，rustup 还想自己恢复，结果被残留目录卡住（os error 145）。处理办法是先 `rustup toolchain uninstall stable`，再手动清掉 toolchains、tmp、downloads 里的残留，然后全新安装。
- **项目 `rust-toolchain.toml` 写死了 1.96.0**，cargo 会自动去下载这个版本，但下载过程中卡住、六分钟没有写入。Rust stable 向后兼容，就用环境变量 `RUSTUP_TOOLCHAIN=stable` 覆盖，直接拿已装好的 1.99.0 编译，省得干等。开发期用 stable，发版再对齐指定版本。
- **两个 cargo 命令同时跑会争 target 目录的锁**，后启动的那个会一直 Blocking waiting。以后同一时刻只跑一个编译任务。
- Windows 上编译 server 要设 `QINGJIAN_UIACCESS=0`。它的 build.rs 默认往 exe 里嵌 uiAccess 清单，没签名的测试程序带着这个清单起不来（os error 740）。
